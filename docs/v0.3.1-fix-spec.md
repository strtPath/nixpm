# nixpm v0.3.1 — fix spec (rev 4, SIGNED OFF)

Status: SIGNED OFF by seniordev 2026-11-16 — "R1-R11 as specified:
✅ ship it." Remaining review items landed as annotations below.
Line citations re-verified against bin/nixpm @ dev == main == v0.3.0.

## Context

Cross-machine test campaign (2026-11-16) against the published default
branch (main == dev == v0.3.0):

- Clean Arch Linux container on a 4GB VM: README one-liner install and
  all setup steps passed; the first `nixpm search hello` (cold index
  build) took the whole VM down — load 21, then SSH and tailscale ping
  dead; needed hypervisor reset. No OOM kill: total thrash.
- Raspberry Pi class host (904MB + zram): cold full-index eval is
  guaranteed to freeze it (not run to completion there on purpose —
  that host runs the mesh transport).
- `nixpm search 'lib(foo'` reproduces an awk crash on the dev box
  (`fatal: invalid regexp`, rc=2, script dies mid-command under
  `set -euo pipefail`).
- `nix-env -q --out-path` emits `bin=/nix/...;man=/nix/...` for
  multi-output packages; `cmd_apps` parsing never finds their
  applications.
- On a host without nix, `nixpm help` and `nixpm --version` exit 1 with
  a message containing a literal `\n`. And `scripts/install.sh` (line
  ~14) outright refuses to install nixpm without nix — one step before
  a user ever gets a binary.

Funnel summary: README one-liner refuses without nix → first nixpm
command on a fresh machine is a broken error → first search freezes
≤4GB machines. That is the adoption cliff.

## R1 — help/version must not require nix

Current: `main()` calls the nix-presence check before any dispatch
(bin/nixpm line 877), so `nixpm help`, `nixpm --version`, and bare
`nixpm` all die on a machine without nix.

Change: single whitelist check at dispatch — `help`, `--version`, `-h`,
`-V` run without the nix preflight; every other command goes through
the existing guard ONCE (do not add per-command guards that can
diverge from a guard left in main).

Acceptance:
- container without nix, binary copied in: `nixpm --version` rc=0
- same: `nixpm help | head -1` rc=0
- same: `nixpm install hello` fails with the nix-not-installed message
  and rc=1 (not a crash).

## R2 — fix the nix-absent error message

`die "... \n ..."` prints via `printf "==> %s\n"`, so `\n` renders
literally. Use two separate `err` calls (no `%b` — it is one escaped
package name away from injection and buys nothing). Acceptance:
renders as two lines.

## R3 — cold search must not freeze modest machines (rewritten per review)

Verified facts: first search evaluates all of nixpkgs
(`_build_search_index`, line 234: `_nix_x search "$NIXPM_NIXPKGS" "^"
--option workers "${NIXPM_SEARCH_WORKERS:-4}" >"$tmp" 2>/dev/null`).
The env knob EXISTS (line 41, documented line 859) — but the default
is RAM-blind, nix's progress (stderr) is discarded, and exactly one
line is printed (line 372) before minutes of silence. On 4GB: full VM
hang (observed); a full-index eval is not viable below ~6GB.

Change:
1. RAM gate, container-aware: effective memory = MIN(MemTotal from
   `/proc/meminfo`, cgroup limit if present — `/sys/fs/cgroup/memory.max`
   v2 or `memory/memory.limit_in_bytes` v1; treat "max"/huge as
   absent). If effective < `NIXPM_MIN_INDEX_MEM_MB` (default 6144),
   do NOT evaluate nixpkgs at all: `nix search` with any query is a
   full eval too, so the "live search" fallback (line 384) must NOT be
   reached in low-RAM mode. Instead print a notice and exit 3 (3 =
   "cannot run", distinct from 1 = no-match; document in help and in
   R1's acceptance table):
   "low-RAM mode: nixpkgs index/search needs ~6GB (found XGB). Install
   packages directly by name — `nixpm install <name>` instantiates
   only that one attr, never the full set — or set
   NIXPM_MIN_INDEX_MEM_MB=0 to try anyway."
   (Guard: `install`/`remove`/`list`/etc. never gated — they never
   full-eval.)
2. Workers: verified DEAD KNOB on upstream nix — `nix --option
   workers 4 eval …` on nix 2.35.6 prints "warning: unknown setting
   'workers'" (reproduced 2026-11-16). Keep passing
   `NIXPM_SEARCH_WORKERS` through (harmless; real on Determinate
   Nix's parallel eval), label it in help as no-op on upstream nix,
   and do NOT acceptance-test "workers ≤ cap" — unobservable, rots
   into false green. The RAM gate (1) is the real protection.
3. Heartbeat: while the build runs, print a progress line to stderr
   every ~10s ("building index… Ns"). The ticker MUST be killed by a
   trap on EXIT/INT — an orphaned background ticker prints
   "building index… 80s" over the NEXT command. Assert on OUR
   heartbeat, not nix's output (stderr is redirected to /dev/null
   today).
4. Honest docs: fix the help lie — line 866 says the index is "built
   by the first search / 'nixpm update'" while the code comments
   (lines 177–178) deliberately exclude `update` from building it.
   Correct the sentence; state first search = minutes on small
   machines, cached after (NIXPM_SEARCH_TTL).

Acceptance:
- low-RAM unit test with a `nix` shim on PATH that logs invocations:
  force `NIXPM_MIN_INDEX_MEM_MB` above effective RAM → notice + rc=3
  and ZERO nix-search calls logged (proves no eval, not just a
  slower eval).
- detection unit: fake cgroup file smaller than MemTotal → gate uses
  the cgroup value.
- clean-arch container on a 4GB VM: `nixpm search hello` → notice,
  host stays ssh-able.
- on a ≥8GB box: heartbeat lines appear during cold build; workers ≤
  computed cap.
- help text no longer claims update builds the index.

## R4 — search query must not crash the cached fast path

Current: the query enters awk as `awk -v re="$query"` then dynamic
`name ~ re` / `line ~ re` (lines 259–264). Regex metacharacters
(`lib(foo`) abort awk (rc=2); inside a command substitution under
`set -euo` the script dies mid-command. The live path handles the same
input differently — fast and slow paths disagree.

Change: escape ERE metacharacters in `$query`, then pass the pattern
via the ENVIRONMENT (`RE="$escaped" awk '… name ~ ENVIRON["RE"] …') —
NEVER via `awk -v re=…`, because `-v` processes backslash escapes and
silently strips the pre-escaping. No gawk `\Q` (mawk lacks it).
Additionally wrap the fast path so awk failure falls back to the live
path rather than dying. Escaper must be TOTAL: handle a trailing lone
backslash in the query, and never allow an empty `ENVIRON["RE"]` to
reach the match (`~ ""` matches every package) — empty query already
rejected upstream by `cmd_search`, guard again at the escaper.

Acceptance (warm cache and cold):
- `nixpm search 'lib(foo'` → normal no-match, rc=1, no awk error.
- `nixpm search 'c++'`, `nixpm search 'a.b'` literal on the fast path
  (document: queries are literal strings in v0.3.1). Fast-path unit:
  index fixture containing `libc` and `aXb` lines — `search 'a.b'`
  must NOT match `aXb` (proves pattern survived escaping intact).

## R5 — `apps` misses multi-output packages

Current parsing assumes one whitespace-separated path per line;
multi-output packages print `attr=/nix/store/...;attr2=...`, so the
computed applications dir never exists.

Change: parse the `--out-path` field list; for each path (strip any
`attr=` prefix, split on `;`), test `<path>/share/applications`.

Acceptance: two tiers —
- Fast shim unit (~100ms, no store write): fake `nix-env` on PATH
  emitting a synthetic `bin=/fake;man=/fake` out-path line; `cmd_apps`
  must find the applications dir under the `bin=` path.
- Real e2e: `geany` (reviewer-verified multi-output on nixpkgs:
  out/dev/doc/man, ships geany.desktop) — install it, `nixpm apps`
  lists it.

## R6 — global flags accepted on either side of the subcommand

`--no-restart` is parsed only in main's pre-subcommand loop (line 885),
so BOTH `install hello --no-restart` AND `install --no-restart hello`
currently treat the flag as a package name. Parse global flags out of
full argv before dispatch; unknown `-…` tokens before the subcommand
stay fatal. Scope discipline: only `--no-restart` needs
post-subcommand honouring; keep `-h`/`-V` pre-dispatch only; do NOT
consume command-specific flags that follow the subcommand (e.g.
`prune --gc` stays prune's).

Acceptance: both spellings install hello and skip menu restart.

## R7 — CI: clean-container e2e

Add a job: `archlinux:latest` container, stranger path, in this order
(no-nix checks FIRST — installing nix via pacman makes the Arch package
create /nix itself and hides both the R1/R2 and R9 conditions):
1. no-nix UX checks (R1/R2 acceptance) by copying `bin/nixpm` straight
   into PATH (install.sh refuses without nix until R8 lands).
2. pacman install nix/curl/jq; /nix bootstrap (`mkdir -m 0755 /nix &&
   chown`, `sandbox = false` in the test's nix.conf) — same bootstrap
   the README must document (R9).
3. subscribe nixpkgs-unstable.
4. install nixpm from the working tree via install.sh.
5. `install hello`, `list`, `list-derivations`, `apps`, `generations`,
   `prune 1`, `remove hello`.
6. R3 low-RAM unit: force `NIXPM_MIN_INDEX_MEM_MB` above the runner's
   effective RAM → notice + rc=3 + zero nix-search calls (nix shim
   logs invocations). Detection unit with fake cgroup file. Heartbeat
   not asserted in CI. R11 unit: `nixpm upgrade` gated (zero
   `nix-env -u` calls); targeted `upgrade hello` passes.
7. R4 regex-query checks (fixture-based, no eval).

Harness INLINE in the workflow YAML (scripts/ today contains only
install.sh; do not add a second home for it in 0.3.1). Every step
isolated with its own rc echo; no abort-on-failure.

## R8 — install.sh must not refuse to install without nix

Line ~14 exits 1 when nix is absent — the funnel's first dead end.
Install nixpm anyway, print the nix-install pointer as a warning, and
let nixpm's own (fixed) guard self-report at first use.

Acceptance: fresh container, no nix: one-liner installs binary;
`nixpm --version` rc=0; `nixpm install x` clean rc=1 message.

## R9 — document /nix bootstrap in README

Non-NixOS first-run on plain Linux needs (as a 3-line pre-req note +
link): `sudo mkdir -m 0755 /nix && sudo chown <user> /nix` (or run the
official installer, which does this). Without it, the official nix
installer fails unattended (proven on rpi3; CI containers need it too).

## R10 — bash-version honesty

`cmd_generations` uses `mapfile` (line 756 — the only occurrence in
bin/nixpm) — bash ≥4 only. macOS ships bash 3.2; README advertises
macOS. Add a startup guard: `(( BASH_VERSINFO[0] < 4 )) && die "nixpm requires bash >= 4 (found $BASH_VERSION)"`
or replace mapfile with a read loop. Prefer the guard for 0.3.1,
rewrite later if macOS support is real.

## R11 — `upgrade` is the same box-bricker; gate it in this release too

Verified in code: `cmd_upgrade` runs `nix-env -u` / `nix-env -u
--dry-run` (`_preview_updates`), which instantiates the FULL package
set to compare versions — identical freeze mechanism to cold search,
ungated, and `nixpm upgrade` is a headline command in README. Reviewer
required it in v0.3.1, not v0.3.2 ("same box-bricking mechanism the
spec exists to remove").

Change: apply the R3 effective-memory gate to the upgrade path — below
threshold, refuse the full `-u` scan with the same notice style +
rc=3, and suggest targeted upgrades: `nixpm upgrade <pkg>` instantiates
only that attr's comparison (verify targeted path stays ungated).

Acceptance: 4GB clean-arch container: `nixpm upgrade` → notice, rc=3,
zero `nix-env -u` calls (nix-env shim logs invocations); `nixpm
upgrade hello` still works.
